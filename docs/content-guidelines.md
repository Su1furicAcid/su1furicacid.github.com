# Content Guidelines

## Pages and Directories

- English pages live directly under `docs/`.
- The site root (`/`) is the About page (`docs/index.md`).
- Blog posts are organized by topic, for example `blog/Program-Verification/`.
- Blog index and Blog sidebar are generated automatically from `docs/blog/**/*.md`.
- Do not manually edit blog links in `docs/blog/index.md` or VitePress sidebar config.

## Blog Directory Structure

The blog supports up to two directory levels under `docs/blog/`:

```
docs/blog/
├── index.md                       # Blog index page (auto-generated listing)
├── <Topic>/                       # Level 1 — required, becomes a top-level sidebar group
│   ├── <post>.md                  # post directly under a topic
│   └── <Subtopic>/                # Level 2 — optional, becomes a nested sidebar group
│       └── <post>.md
```

- Level 1 (`<Topic>`) is required for every post. It is derived from the first URL segment after `/blog/` and is used as the top-level grouping in the sidebar and blog index.
- Level 2 (`<Subtopic>`) is optional. When present, posts are nested under a collapsible sub-group inside their topic. Posts sitting directly under a topic (no subtopic) are listed at the topic level.
- Topic labels are generated by splitting the directory name on `-` or `_` and title-casing each part (e.g. `Program-Verification` -> `Program Verification`).
- Subtopic labels preserve the raw directory name verbatim, including hyphens and underscores (e.g. `15-779` -> `15-779`). This keeps identifiers like course numbers intact.

Examples:

| File path | Topic | Subtopic | URL |
|---|---|---|---|
| `blog/Program-Verification/k-induction.md` | Program Verification | — | `/blog/Program-Verification/k-induction` |
| `blog/MLSys/15-779/02-basics.md` | MLSys | 15-779 | `/blog/MLSys/15-779/02-basics` |

## Blog Frontmatter Convention

Each blog post must include:

```yaml
title: string
date: YYYY-MM-DD
summary: string
tags:
  - string
```

- `title` and `date` are required for build-time indexing.
- `summary` and `tags` are optional but recommended.

## Images

Every post keeps its images in a subfolder named after the post (without extension), right next to the markdown file. This keeps every post self-contained: easy to move, rename, or delete without leaving orphaned assets, and VitePress processes co-located images through its asset pipeline (hashed URLs, optimized serving).

```
docs/blog/MLSys/15-779/
├── 02-basics.md
└── 02-basics/
    ├── pipeline.png
    └── memory-layout.png
```

Reference images with a relative path into the subfolder:

```markdown
![pipeline](./02-basics/pipeline.png)
![memory layout](./02-basics/memory-layout.png)
```

### Automatic image placement on paste

The repo ships a `.vscode/settings.json` that configures VS Code's built-in markdown paste support so that screenshots pasted into a post (Ctrl+V) are automatically saved into that post's subfolder, with no manual filing needed. The same fallback is configured for the Paste Image extension in case it is installed.

For example, pasting a screenshot while editing `docs/blog/MLSys/15-779/02-basics.md` creates the file at `docs/blog/MLSys/15-779/02-basics/img-YYYY-MM-DD-HH-mm-ss.png` and inserts `![](./02-basics/img-....png)` at the cursor — the subfolder is created on demand.

> Do not put blog images in a centralized `docs/public/` directory. `public/` is reserved for assets that must be served verbatim at the site root (e.g. `favicon.ico`) and bypasses VitePress's asset processing.

## Publications Convention

- Group entries by year in descending order.
- Each entry should include title, authors, venue, and links.
